# 本地中文编辑与英文同步

## 打开后台

在本站 source 文件夹的终端运行 `npm run editor`，打开终端显示的地址。默认 http://127.0.0.1:4198/__editor/ 。此窗口运行期间保持终端开启。

后台仅通过上述本地地址单独打开，网站导航及中英文本地预览均不提供后台入口；后台不作为公开网站页面发布。

也可以双击源码目录中的“打开本地编辑后台.cmd”，再点击上面的后台地址。推荐使用 Node.js 22。关闭终端会停止后台，但已保存的磁盘草稿不会丢失。

## 修改已有页面

1. 左侧选择页面，也可按标题、网址搜索。
2. 在预览点击文字，或从右侧“本页文字”选择。右侧编辑中文，英文保留用于核对。共用文字会注明影响范围。
3. 点击“保存中文草稿”，确认顶部显示“已保存本地”。刷新和重新启动后仍会保留。
4. 通过“中文 / English”“电脑 / 手机”检查，或“单独预览”打开完整页面。
5. 在聊天通知：“本站中文草稿已保存，请同步英文，先给本地预览，不部署。”

编辑图片时，在预览中点击图片，从站内图库选择同主题图片并保存。品牌标识锁定，不替换案例为不相关照片；避免重复文章封面。

## 新增文章

点击“＋ 新文章”，填写英文短网址、中文标题、摘要、导语、封面和完整章节。正文用空行分段，不把一句话拆成一个章节。保存后可以在中文 News 和文章页面预览；英文同步前不会出现在英文列表。

## 历史、冲突与存储

“历史版本”可以恢复旧内容，恢复会生成新版本。两个窗口同时编辑时，旧窗口不会覆盖新版本；复制未保存文字、刷新，再按需粘贴。

磁盘草稿：source/.local-editor/draft.json；历史：source/.local-editor/history/。这些文件被 Git 忽略。浏览器缓存清理不会删除磁盘草稿；请自行备份 .local-editor 文件夹，不把真实客户私密信息写入内容。

## 给后续助手的同步流程

读取磁盘草稿，与 src/i18n/content.json 比较。entries 中 source 是稳定英文标识，zh 是中文草稿；同步 en 后把 syncedZh 设为对应 zh。新增 articles 的 english 包含 title、summary、lead、sections[{heading,body}]；syncedChinese 是中文 title/summary/lead/sections 的 JSON 字符串。不得覆盖用户保存后的新版本。

先更新草稿并检查本地；确认要纳入候选构建时，将已审核副本通过 apply_patch 保存到 src/i18n/content.json。生成器负责双语文档和网址规则。不得把未同步文章作为英文发布，也不得让草稿自动进入生产。只有用户针对该版本明确确认部署后，才能走 GitHub → Vercel。
